# フロントエンド設計

> ステータス: **Draft**。React（SPA）+ TypeScript + Vite で実装しています（[ADR 0005](../adr/0005-tech-stack.md)）。

> [!IMPORTANT]
> 現在の画面は **動作検証用の仮 UI** です。対戦の一連の流れを確認するための最低限の画面で、デザイン・UX はまだ検討していません（配色・レイアウト・文言も仮）。正式な UI デザイン（サービスアイコン・Favicon・画面構成の見直しなど）は [#10](https://github.com/tacky0612/smash-hub/issues/10) で進めます。

## 1. 役割

- プレイヤーが **自分のホームインスタンス** を通じて、対戦募集・マッチング・結果報告・レート確認を行うための Web UI。
- フロントエンドはホームインスタンスの Backend とだけ通信します。他インスタンスとの通信はすべて Backend が担います。
- 同じフロントエンドを全インスタンスで共通に使い、インスタンスごとの差分（名称・ルール・利用規約）は設定で切り替えます。

## 2. 主要画面（初期）

下表は想定している画面です。仮 UI で実装済みなのは、ログイン・登録・レーティング対戦・対戦ルーム・ランキング・プロフィール（戦績）・設定（プロフィール編集とログアウトのみ）です。

| 画面 | 内容 |
|---|---|
| トップ | 自分のレート、レーティング対戦への入口、インスタンスの案内 |
| 登録 / ログイン | 外部プロバイダー（Discord / Google）でのログイン、表示名の設定、リカバリーキーの発行と保管の案内 |
| レーティング対戦 | 1戦目のファイターとレート差を選んで「対戦相手を探す」、マッチング待ち（成立は音でも通知） |
| 対戦ルーム | 部屋 ID・パスワードの共有、拒否ステージと選べるステージの表示、ファイター変更、メッセージ、結果報告（勝ち / 負け / 対戦中止） |
| プロフィール | 戦績、レート推移、使用ファイター（テキスト表記） |
| ランキング | シーズン・インスタンス範囲ごとのランキング |
| 設定 | プロフィール編集（メインファイター・ゲーム内の名前）、拒否ステージ、スイッチ、対戦設定（連戦・接続・配信・動画化）、ブロック、データエクスポート、アカウント移行・削除 |
| インスタンス情報 | 運営者、連合先、利用規約、[ポリシー](../policy.md) の表示 |
| フッター（全画面） | 非公式表示・商標表示、ソースコードへのリンク（[AGPL-3.0](../../LICENSE) 第13条への対応） |

## 3. 方針

- **スマートフォン優先** — 対戦中はスマートフォンで操作されることが多いため、モバイルでの操作性を最優先する。
- **公式素材を使わない** — ファイターはテキスト（名称・略称）で表示し、画像・アイコンは使わない（→ [運営ポリシー](../policy.md)）。プロジェクト独自のデザインで、公式の意匠に寄せない。
- **リアルタイム性** — マッチング成立・相手の入室・相手の報告はリアルタイムに通知する（マッチング成立は音でも知らせる）（当面は3秒間隔のポーリング。必要になれば SSE / WebSocket に置き換える）。
- **軽量・静的配信可能** — インスタンス運営者の負担を減らすため、静的ファイルとして配信できる構成を優先する。
- **アクセシビリティ** — 色だけに依存しない勝敗表示、キーボード操作、スクリーンリーダー対応。
- **トークンを持たない** — 認証はバックエンドが外部プロバイダーとやり取りし、ブラウザには `HttpOnly` のセッション Cookie だけを渡す。`localStorage` にトークンを保存しない（→ [認証](../security/authentication.md)）。
- **国際化の余地** — 当初は日本語のみ。文言は最初から辞書ファイルに分離しておく。

## 4. ディレクトリ構成

```
frontend/
├── src/
│   ├── api.ts          # バックエンド API のクライアント（型定義・CSRF ヘッダー）
│   ├── context.tsx     # ログイン状態・ファイター一覧などの共有状態、ポーリング
│   ├── App.tsx         # ルーティング・ヘッダー・フッター（非公式表示・ソースコードへのリンク）
│   └── pages/          # 画面
├── nginx.conf          # 本番イメージ: 静的配信と /api のバックエンドへの転送
└── security-headers.conf  # CSP などのセキュリティヘッダー
```

- 画面から API を直接呼ばず、`api.ts` を経由します。
- 外部の CDN・解析スクリプト・フォントは読み込みません（CSP で `'self'` のみ許可）。
