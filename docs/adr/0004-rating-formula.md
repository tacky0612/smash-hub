# 0004: レーティングの計算式にスマメイト式を採用する

- ステータス: Accepted
- 日付: 2026-10-26

## 背景

- 当初は、記録の到着順に依存しにくい Glicko-2 を第一候補にしていた。
- 一方で、利用者はスマメイトの「対戦ごとにすぐレートが動く」仕組みに慣れており、同じ感覚で使えることが求められる。
- 連合のどのインスタンスでも同じレートになる（決定的である）必要がある。

## 検討した選択肢

1. **Glicko-2（期間ごとに更新）** — 到着順に依存しないが、対戦直後に変動が見えない。2人の増減が非対称で分かりにくい。
2. **Elo（K=32）** — 対戦ごとに更新できるが、小数が出るため実装間で 1 ずれることがある。スマメイトの実際の変動とも一部一致しない。
3. **スマメイト式** — `floor(16 + (敗者 − 勝者) ÷ 25)`、最小 1・最大 30、敗者は 1000 未満にならない。スマメイトの実際の変動とよく一致する。

## 決定

選択肢 3（スマメイト式）を採用する。詳細は [レーティング](../domain/rating.md) に定める。

- メインシーズンのみ（約2か月）。シーズン開始時は全員 1500。置き戦は設けない。他サービスの過去レートは引き継がない。
- レートはプレイヤー単位のみ（ファイター別レートは提供しない）。
- 表示はレートの値そのもの。ランキング掲載はシーズン 20戦以上。

## 理由

- スマメイトの利用者が同じ感覚で使える。
- 整数演算だけで計算でき、言語・環境による差が出ない。
- 対戦の処理順（`played_at` → 記録 ID）と取り込みの締め切り（7日）を定めることで、逐次更新でも連合内で同じ結果にできる。

## 影響

- 遅れて届いた記録があると、その時点以降の再計算が必要になる。7日の締め切りで再計算の範囲を限定する。
- 対戦直後のレートは暫定レートとして表示し、7日経過で確定する。
