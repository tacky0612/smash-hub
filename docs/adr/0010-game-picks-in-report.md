# 0010: ゲームごとのファイターは結果報告で任意に入力し、両者の入力が一致したときだけ対戦記録に含める

- ステータス: Accepted
- 日付: 2026-10-27
- 関係者: @tacky0612

## 背景

対戦記録（`MatchRecorded`）の `picks` には、これまで1戦目のファイター（マッチングで選んだもの）しか入っていませんでした。標準ルールは2本先取で、2・3戦目に敗者がファイターを変えられるため、ゲームごとのファイターを記録したいという要望があります。

対戦記録は両プレイヤーが同じ内容に署名して確定し、連合で共有した後は変更できません（[SmashHubプロトコル](../architecture/federation.md) の 12）。署名は結果を報告した時点で行うため、署名する内容に含める項目は、両者が報告の時点で同じ値を入力していなければなりません。また、対戦の進め方は「決着後に1回だけ結果を報告する」形のままにします（ゲームごとに画面で進行しない）。

## 検討した選択肢

1. **勝者だけを署名し、ゲームごとの内容はインスタンスの中だけで持つ** — 入力ミスで確定が止まらない。ただし、ゲームごとのファイターは連合で共有されず、検証もできない。
2. **ゲームごとの勝敗・ファイター・ステージをすべて署名して共有する** — 詳しい記録になる。ただし、2人の入力が完全に一致しないと確定しないため、入力ミスがそのまま食い違いになり、報告の手間も大きい。
3. **ゲームごとのファイターだけを署名する（入力は必須）** — 現在の仕様（`picks`）どおり。ただし、ファイターの入力ミスで確定が止まる。
4. **ゲームごとのファイターを任意で入力し、一致したときだけ署名した記録に含める** — 報告者は「1戦目だけの内容」と「ゲームごとのファイターを含めた内容」の両方に署名する。勝敗が一致すれば確定し、ファイターも一致していれば後者、そうでなければ前者を記録にする。

## 決定

選択肢 4 を採用します。

- 結果報告では、勝ち・負け・中止を必須、ゲームごとのファイター（2〜3ゲーム分、両者の分）を任意で入力する。
- 勝敗の報告には、報告者が **1戦目だけの対戦結果の内容** と、ファイターを入力した場合は **それを含めた内容** の両方に署名する。
- 確定の条件は勝敗の一致だけとする。両者のファイターの入力が一致すれば、それを含めた内容と署名で記録する。一致しない・片方だけが入力した場合は、1戦目だけの内容と署名で記録する。
- 1戦目だけの記録の `picks` は、マッチングで選んだファイターとする（おまかせで参加した側は `random` のまま）。
- ゲームごとの勝敗とステージは入力しない（記録しない）。
- 報告を受け付けるとき、ゲームごとのファイターが標準ルールに沿っているかを検証する（2〜3ゲーム、`random` は不可、1戦目はマッチングで選んだファイター、2・3戦目にファイターを変えたのは直前のゲームの敗者だけ）。ゲームごとの勝敗は報告しないが、対戦の勝者が分かれば各ゲームの勝敗の並びは限られる（2ゲームなら勝者の2連勝、3ゲームなら勝者が1戦目か2戦目のどちらかで負けた2通り）。そのどれかと矛盾しないことを確かめる。
- 連合から取り込む記録では、`picks` の **形** だけを検証する（1〜3ゲーム、連番、2人分のファイター ID の書式。`random` は1戦目だけの記録に限る）。自インスタンスのファイター一覧にない ID も取り込む。新しいファイターの ID を追加したバージョンのインスタンスの記録で、同期が止まらないようにするため。

## 理由

- 記録の確定がファイターの入力ミスで止まらない。勝敗の一致という今までの確定条件を変えずに済む。
- 記録に含めるファイターは、両者が同じ内容に署名したものだけになり、連合のどのインスタンスでも検証できる（一方的な申告が記録に混じらない）。
- 報告の時点で署名できるため、インスタンスをまたぐ対戦でも、ホームインスタンスからホストへ報告を1回中継するだけで済む（署名を後から集める往復が要らない）。
- ゲームごとの勝敗を入力しなくても、対戦の勝者から勝敗の並びの候補を絞れるため、「勝者がファイターを変えていない」ことは確かめられる。

## 影響

- 報告1件につき最大2つの署名を作り、ホストは両方を検証する。`POST /federation/match-reports` に `picks` と `picks_sig`、対戦の状態（`GET /federation/matches/{id}`）に各プレイヤーの報告した `picks` を加えた。どちらも入力がなければ省略するため、ファイターを入力しない報告は従来の形のままになる。
- 記録 ID は署名した内容から計算するため、ファイターを含めた記録とそうでない記録では記録 ID が変わる（同じ対戦から記録が2つできることはない。確定時にどちらか1つだけを記録する）。
- 1戦目だけの記録には `random` が残りうる。[ファイター ID](../domain/fighters.md) の方針にこの例外を書き足した。
- 2-1 の対戦で、勝敗の2通りの並びのどちらにも矛盾しないファイターの変更（例: 変更なし）は、どちらの並びだったかまでは分からない。ゲームごとの勝敗を記録したくなったら、新しい ADR で見直す。
