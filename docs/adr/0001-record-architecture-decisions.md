# 0001: 設計判断を ADR で記録する

- ステータス: Accepted
- 日付: 2026-10-26

## 背景

SmashHub は、特定の開発者・運営者に依存しないことを目指す OSS である。開発者が入れ替わっても設計判断の理由を追えるようにする必要がある。

## 決定

重要な設計判断（技術選定、プロトコル、データ形式、ポリシーに関わる判断）は ADR として `docs/adr/` に記録し、PR のレビューを経て確定する。

## 影響

- 判断の経緯がリポジトリに残り、新しいコントリビューターが参加しやすくなる。
- 判断ごとに ADR を書く手間が増える。小さな判断では ADR を書かなくてよい。
