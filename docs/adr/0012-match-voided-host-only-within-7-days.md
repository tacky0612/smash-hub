# 0012: 対戦記録の無効化は、記録のホストだけが対戦から 7日以内に発行できる

- ステータス: Accepted
- 日付: 2026-10-27
- 関係者: @tacky0612

## 背景

- 八百長・虚偽の報告などがあった対戦は、確定した後でもレート計算から除外する必要があります（[対戦ルール](../domain/match-rules.md) の「10.3 対応の段階」）。記録は不変なので、取り消しはログへの `MatchVoided` の追記で表します（[SmashHubプロトコル](../architecture/federation.md) の「5.2 イベント種別」）。
- レートは連合全体で1つ（SmashHubレート）です。どのインスタンスでも、同じ記録の集合から同じレートを計算できなければなりません（[レーティング](../domain/rating.md) の「4. 決定性を守るための約束」）。無効化をどのインスタンスが発行でき、いつまで有効にするかを、全インスタンスで同じに決める必要があります。
- 確定レートは「`played_at` から 7日経過した範囲は以後変わらない」と約束しています。期限のない無効化は、この約束を破ります。

## 検討した選択肢

### 無効化を発行できるインスタンス

1. **記録のホストだけ** — 無効化は記録と同じログの後ろに追記されるので、受信側は「発行元が記録のホストか」を見るだけで検証できる。記録より先に無効化が届くこともない。他インスタンスの利用者の不正には、ホストの運営者に依頼する必要がある。
2. **ホストと、両プレイヤーのホームインスタンス** — 自インスタンスの利用者の不正に直接対応できる。ただし無効化と記録が別のログに載るため、記録より先に無効化が届く場合の扱いと、検証の手順が複雑になる。

### 無効化の期限

1. **期限なし** — 後から発覚した不正にも対応できる。確定レートが無効化によっていつでも変わり得る。
2. **対戦から 7日以内** — 取り込みの締め切りと同じ考え方で、確定レートが本当に変わらなくなる。7日を過ぎてから発覚した不正の記録は、レート計算に残る。

## 決定

- `MatchVoided` を発行できるのは、**記録のホストインスタンスだけ** とします。受信側は、無効化の発行元が記録の `host_instance` と一致しない場合、その無効化を受理せず、そこで取り込みを止めます（他の検証の失敗と同じ扱い）。
- 無効化が有効なのは、ホストがログに追記した日時（イベントヘッダの `created_at`。ホストの署名対象）と記録の `played_at` の差が **7日以内** の場合だけです。7日を過ぎた無効化もログとしては取り込みますが、レート計算では無視します。ホストのインスタンスは、期限を過ぎた無効化を発行しません。
- payload は記録 ID と事由の区分だけにします。事由は `collusion`（八百長）・`cheating`（改造・チート・不正な入力機器）・`false_report`（虚偽の報告）・`error`（記録の誤り）・`other` です。連合で共有されるため、自由記述は持ちません（個人情報を含めない）。新しいバージョンで追加された区分も取り込めるよう、受信側は書式（英小文字と `_`）だけを確かめます。
- 同じ記録への無効化が2回以上あった場合は、先に追記されたものを使います（2回目以降は何もしない）。無効化の取り消しは扱いません。

## 理由

- **決定性を保てる** — 発行元の判定はイベントヘッダだけで、期限の判定はホストが署名した日時だけで決まります。到着順や各インスタンスの時計に依存せず、どのインスタンスでも同じ記録の集合になります。
- **確定レートの約束を守れる** — 取り込みの締め切りと同じ 7日にそろえることで、`played_at` から 7日を過ぎた範囲のレートは、記録の追加でも無効化でも変わりません。
- **実装と検証が単純** — 記録と無効化が同じログに載るので、記録が見つからない無効化は不正なイベントとして扱えます。
- **モデレーションは各インスタンスの責任** — 対戦を受け付けたホストが、その対戦の記録に責任を持ちます。インスタンスをまたいだモデレーションの連携は、ロードマップ Phase 4 で扱います。

## 影響

- 7日を過ぎてから発覚した不正は、記録の無効化ではなく、利用停止などの処分で対応します。
- 他インスタンスがホストした対戦の不正は、ホストの運営者に依頼する必要があります。依頼の手段（通報の転送）は Phase 4 のモデレーション連携で用意します。
- ホストのインスタンスが閉鎖した後は、その記録を無効化できなくなります。閉鎖の手順（ADR 0009 の管理画面の閉鎖機能）を整備するときに、未対応の通報を片付けてから閉鎖するよう案内に含めます。
- 後から見直す条件: 7日を過ぎてから発覚する不正が多く、ランキングの信頼に影響する場合。その場合は、確定レートの約束とあわせて新しい ADR で見直します。
