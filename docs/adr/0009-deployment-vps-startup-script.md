# 0009: インスタンスは国内 VPS のスタートアップスクリプトで立ち上げる

- ステータス: Accepted
- 日付: 2026-10-26
- 関係者: @tacky0612

## 背景

- インスタンスの運営者として想定しているのは IT 技術者ではなく、スマブラのコミュニティの世話役です。運営者が増えなければ分散の意味がありません（[議論資料](../operations/easy-deployment.md)、[#1](https://github.com/tacky0612/smash-hub/issues/1)）。
- バックエンドは Go の単一バイナリ、DB は PostgreSQL、フロントエンドは静的ファイルで、Docker Compose で動きます（[ADR 0005](0005-tech-stack.md)）。
- 連合では、インスタンスは URL と署名鍵で識別されます（[SmashHubプロトコル](../architecture/federation.md)）。URL が変わると連合先から見て別のインスタンスになります。

## 検討した選択肢

1. **VPS + Docker Compose + セットアップスクリプト（SSH で実行）** — 自由度が高く、費用も安定している。ただし SSH とターミナルの操作が必要。
2. **VPS 事業者のスタートアップスクリプト（1. のスクリプトを申込画面から実行）** — ブラウザの操作だけで完結する。スクリプトは事業者に依存しない形で書ける。
3. **PaaS のワンクリックデプロイ** — 操作は最も少ない。ただし無料枠の縮小・料金改定や、DB の永続化に左右される。
4. **サーバーレス / エッジの無料枠** — 無料で、サーバーの管理も要らない。ただし Go + PostgreSQL の構成を大きく変える必要があり、特定の事業者に依存する。
5. **自宅の PC / Raspberry Pi + トンネル** — 追加費用はほぼゼロ。ただし常時稼働・停電・回線の問題がある。
6. **GitHub の fork + GitHub Actions** — 無料でサーバーも要らない。ただし記録の保全（ミラー）にしか使えない。

## 決定

### 想定する運営者

[議論資料の運営者像](../operations/easy-deployment.md#2-想定する運営者像たたき台) のとおりです。

- ターミナル・SSH・Linux・DNS・TLS 証明書の知識は要らない。
- Discord サーバーを管理できる程度の操作ができる。
- 運営に使える時間は月に数時間。

独自ドメインを使う場合に、DNS に A レコードを1つ追加する作業だけはお願いします。その作業には画面ごとの手順書を用意します。

### フル機能のインスタンス

- **公式に推奨する手順は、国内 VPS のスタートアップスクリプト（選択肢 2）とします。** 運営者は VPS の申込画面で公式のスクリプト（または、その URL）を指定するだけで、SSH は使いません。
- スクリプトは cloud-init / bash で書き、事業者に依存させません。同じスクリプトを SSH で手動実行することもできます（選択肢 1。技術者向け）。
- 手順書と動作確認の対象にする事業者と、費用の目安は次のとおりです。

  | 事業者 | プラン | 月額の目安（税込） | スタートアップスクリプト |
  |---|---|---|---|
  | さくらのVPS | 1GB | 807〜990 円（リージョン・支払い方法による） | マイスクリプトとして登録する |
  | ConoHa VPS | 1GB | 763 円（1か月契約）。時間課金もある | テキスト入力、または URL を指定する |

  運営者の費用は **月 1,000 円前後 + 独自ドメイン代** を目安とし、メモリ 1GB の VPS で動く構成を保ちます。料金は 2026年10月時点のものです。手順書では公式サイトで最新の料金を確認するよう案内します。

### ドメインと HTTPS

- 本番では **独自ドメインを推奨** します。連合で使うインスタンスの URL を変えずに済むようにするためです。
- 試すだけなら、VPS の IP アドレスから作る無料のサブドメインでも起動できます。ただし、URL が IP アドレスに結びつくため、試用のインスタンスは連合に参加させません。本番では独自ドメインに切り替えてから連合に参加してもらいます。
- HTTPS の証明書は、どちらの場合も自動で取得・更新します。

### 初期設定

- スクリプトは書き換えずにそのまま使います。秘密情報（インスタンスの署名鍵・識別子ペッパー・アカウント鍵の暗号化鍵・DB のパスワード）は、スクリプトがサーバー上でランダムに生成します。運営者が入力したり、目にしたりすることはありません。
- ドメイン・インスタンス名・Discord アプリのクライアント ID とシークレットは、**初回起動時のブラウザのセットアップ画面** で入力してもらいます。
- 起動から設定までの間にセットアップ画面を第三者に乗っ取られないよう、ワンタイムコードを VPS のコンソール画面（事業者のコントロールパネルから開ける）に表示します。セットアップ画面ではこのコードの入力を求めます。
- セットアップ画面で運営者の Discord アカウントを紐づけ、そのアカウントを管理者にします。

### 運用

- **アップデート:**
  - OS のセキュリティ更新は自動で適用します。
  - SmashHub 本体は、新しいリリースを管理画面に通知し、運営者がワンクリックで更新します。
  - セキュリティ修正のリリースだけは自動で適用します。
- **バックアップ:**
  - DB のバックアップは毎日サーバー内に自動で作り、管理画面からダウンロードできます。
  - 秘密情報（署名鍵・ペッパー・暗号化鍵）は、[データ保護](../security/data-protection.md) の方針に従い、DB とは別のファイルにします。セットアップの完了時と変更時に、管理画面からダウンロードするよう案内します。
  - どちらのファイルも、セットアップ画面で決めたパスフレーズで暗号化します。手順書では、2つのファイルを別々の場所に保管するよう案内します。
  - 確定した対戦記録は連合先にも複製されます。そのため、特に失うと困るのは鍵とペッパーです。
- ヘルスチェックと異常時の通知、閉鎖の手順（閉鎖予告・最終複製）も管理画面から行えるようにします。

### 記録の保全だけを行う場合（ミラー・静的アーカイブ）

- フル機能とは **手順を分けます**。
- サーバーを持たない人向けには、**リポジトリを fork して GitHub Actions を有効にするだけ** で、連合先のログを pull・検証し、静的アーカイブとして公開できるようにします（選択肢 6）。
- VPS を使う [ミラー](../domain/README.md) も用意します。手順はフル機能と同じスクリプトで、設定でミラーにします。

## 理由

- **運営者が触れるのはブラウザだけ** — VPS の申込画面とセットアップ画面・管理画面だけで、立ち上げから運用まで完結します。想定する運営者のスキルに収まります。
- **逃げ道がある** — スクリプトは事業者に依存しない cloud-init / bash で、中身は普通の Docker Compose です。事業者の料金改定やサービス終了があっても、別の VPS に同じ手順で移れます。PaaS・サーバーレスの無料枠のような、外部の都合による打ち切りに左右されません。
- **今の構成のまま使える** — Go + PostgreSQL + 静的ファイルの構成（[ADR 0005](0005-tech-stack.md)）をそのまま 1GB の VPS で動かせます。開発環境（`make up`）とも近く、テストしやすいです。
- **費用が安定している** — 国内の 1GB VPS は月 1,000 円前後で、無料枠の変更に左右されません。国内のリージョンなので、国内のプレイヤーからの応答も速いです。
- **保全への参加の敷居を下げる** — 静的アーカイブを GitHub Actions で立てられるようにすると、サーバーを持たない人も記録の保全に参加できます。

## 影響

- [セキュリティポリシー](../security/README.md) で求めている「秘密情報を DB とは別に、安全に保管する」作業は、運営者がダウンロードしたファイルを保管するだけで済むようになります。
- 次のものを実装する必要があります。
  - 公式のセットアップスクリプト（cloud-init / bash）
  - 本番用の Docker Compose 構成（自動で HTTPS 証明書を取る reverse proxy を含む）
  - 初回セットアップ画面
  - 管理画面（更新・バックアップ・通知・閉鎖）
  - 静的アーカイブ用の GitHub Actions ワークフロー
- 秘密情報は、環境変数を直接書く方式から、スクリプトが生成してサーバー上に保存する方式に変わります。開発環境の `compose.yaml` は今のまま使います。
- 本番の最小構成はメモリ 1GB です。依存するミドルウェアを増やすときは、1GB の VPS で動くことを確認します。
- DB は PostgreSQL のままとします。1GB の VPS で動くため、SQLite への対応（[ADR 0005](0005-tech-stack.md) の「影響」）は当面行いません。
- さくらのVPS と ConoHa VPS で、スクリプトの動作を確認し続ける必要があります。事業者の仕様変更でスクリプトが動かなくなった場合は、手順書と対象の事業者を見直します。
- 事業者の公式テンプレートへの掲載（アプリケーションテンプレート等）は、利用者が増えてから検討します。
