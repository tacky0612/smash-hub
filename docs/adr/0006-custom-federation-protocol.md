# 0006: 対戦記録の連合は独自プロトコルで行う

- ステータス: Accepted
- 日付: 2026-10-26

## 背景

インスタンス間で対戦記録を複製し、どのインスタンスでも同じレートを再計算できるようにする必要がある。要件は次のとおり。

- 記録を失わない（完全複製・再配布ができる）
- 改ざん・欠落を検知できる（署名とハッシュチェーン）
- 個人運営の小さなサーバーでも実装・運用できる
- 相手が止まっていても、復帰後に差分を取り直せる

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ActivityPub | Mastodon 等で実績があり、エコシステムが大きい | 記録の完全複製・欠落検知の仕組みを持たない。配信モデルが「投稿の通知」向きで、レート計算の入力としての記録の集合を揃えにくい |
| AT Protocol | 署名付きリポジトリ・アカウント移行の思想が近い | 仕様が大きく、スマブラの対戦記録に必要な部分の切り出しと運用（リレー等）の負担が大きい |
| 独自プロトコル | 必要最小限で理解しやすく、署名付き追記専用ログ・pull 同期・スナップショットを要件に合わせて設計できる | 仕様と実装を自前で保守する必要がある |

## 決定

対戦記録・アカウントの公開情報の連合は **独自プロトコル** で行う。仕様は [SmashHubプロトコル](../architecture/federation.md) に定める。

SNS との連携（プロフィールや対戦結果を Mastodon 等から見られるようにする）は対戦記録の連合とは切り離し、将来 ActivityPub で補完することを検討する（ロードマップ Phase 5）。

## 理由

- 要件（完全複製・欠落検知・決定的なレート計算の入力）を満たす最小の仕組みにできる。
- 個人運営のインスタンスでも、HTTP の pull と署名検証だけで実装できる。
- 仕様が小さく、プロトコルを独自に実装する他のサイトも参加しやすい。

## 影響

- 仕様のバージョン管理（イベントの `version`）と互換性の維持を、プロジェクトが責任を持って行う。
- 既存のフェディバースとはそのままでは相互運用できない。必要な部分は ActivityPub のブリッジで補う。
