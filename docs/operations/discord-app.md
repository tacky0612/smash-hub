# Discord アプリの作成（Discord ログインの設定）

> ステータス: **Draft**。インスタンス運営者向けの手順書です（[#6](https://github.com/tacky0612/smash-hub/issues/6)）。

SmashHub のインスタンスでは、利用者は Discord のアカウントでログインします（[認証](../security/authentication.md)）。そのために、インスタンス運営者が自分の Discord アカウントで「Discord アプリ」を1つ作り、そこで発行される **クライアント ID** と **クライアントシークレット** をインスタンスに設定します。

作業は Discord の開発者向けの画面（Discord Developer Portal）で行い、10分ほどで終わります。費用はかかりません。

> この手順書に出てくる画面の文言は、2026年時点の Discord Developer Portal（英語表示）のものです。Discord の画面は予告なく変わることがあります。文言が見つからないときは、似た名前のメニューを探してください。

## 1. 用意するもの

- Discord のアカウント（ふだん使っているもので構いません）
- インスタンスのドメイン（例: `smash-hub.example.com`）。まだ決まっていなければ、先に [インスタンスの立て方](deployment.md) の「ドメインを決める」を済ませてください

## 2. アプリを作る

1. ブラウザで Discord Developer Portal（<https://discord.com/developers/applications>）を開き、Discord のアカウントでログインします。
2. 「**Applications**」の画面の右上にある「**New Application**」を押します。
3. アプリの名前を入力します。
   - この名前は、利用者が初めてログインするときに Discord の確認画面に表示されます（「○○ があなたのアカウントへのアクセスを求めています」）。インスタンスの名前にすると分かりやすいです。
   - 任天堂や公式のサービスと誤解される名前は避けてください（[運営ポリシー](../policy.md)）。
4. Discord の開発者向けの規約に同意するチェックを入れ、「**Create**」を押します。

アプリのアイコンや説明文は設定しなくても動きます。設定する場合も、ゲームの画面やファイターの画像・ロゴなど任天堂の著作物は使わないでください（[運営ポリシー](../policy.md)）。

## 3. クライアント ID とクライアントシークレットを控える

1. 作ったアプリの画面の左のメニューから「**OAuth2**」を開きます。
2. 「**Client information**」の欄にある「**Client ID**」が **クライアント ID** です。「Copy」で写し、インスタンスの設定ファイルの `DISCORD_CLIENT_ID=` の後ろに貼り付けます。
3. 同じ欄の「**Client Secret**」の「**Reset Secret**」を押します。確認が出たら「Yes, do it!」等で進めます（Discord のアカウントで二要素認証を使っている場合は、そのコードも求められます）。
4. 表示された文字列が **クライアントシークレット** です。**この画面を閉じると二度と表示されません。** すぐに「Copy」で写し、設定ファイルの `DISCORD_CLIENT_SECRET=` の後ろに貼り付けます。
   - 写し損ねた場合は、もう一度「Reset Secret」を押して作り直してください（古いシークレットは使えなくなります）。

設定ファイルの場所と反映のしかたは [インスタンスの立て方](deployment.md#5-設定ファイルを編集する) を見てください。

## 4. リダイレクト URI を登録する

ログインのあと、Discord が利用者をインスタンスに戻すときの行き先（リダイレクト URI）を登録します。登録したもの以外の行き先には戻らないため、不正なサイトへの誘導を防げます。

1. 同じ「**OAuth2**」の画面の「**Redirects**」の欄で「**Add Redirect**」を押します。
2. 次の URL を入力します。`<ドメイン>` はインスタンスのドメインに置き換えてください。

   ```text
   https://<ドメイン>/api/auth/discord/callback
   ```

   例: ドメインが `smash-hub.example.com` なら `https://smash-hub.example.com/api/auth/discord/callback`

3. 画面の下に出る「**Save Changes**」を押して保存します。

> リダイレクト URI は **1文字でも違うと** ログインできません（「Invalid OAuth2 redirect_uri」等と表示されます）。`https://` で始まっているか、ドメインのつづり、末尾に余計な `/` がないかを確認してください。ドメインを変えたときは、新しいドメインの URI を追加し直します。

## 5. 権限（スコープ）について

SmashHub が Discord に求める権限（スコープ）は **`identify`（Discord のユーザーを見分けるための ID を知る）だけ** です。メールアドレス・参加しているサーバー・フレンドなどの情報は求めません。また、受け取った ID もそのままは保存せず、元に戻せない形（識別子ハッシュ）にしてから保存します（[データ保護](../security/data-protection.md)）。

権限はログインのときに SmashHub が自動で指定するため、Developer Portal で設定する必要はありません。「OAuth2 URL Generator」でスコープを選んだり、「Bot」を作ったりする必要もありません。

## 6. クライアントシークレットの扱い

クライアントシークレットは、インスタンスがあなたの Discord アプリとしてふるまうための合言葉です。

- 設定ファイル（サーバー上の `smash-hub.env`）以外に書かないでください。チャット・SNS・スクリーンショット・GitHub の Issue などに貼らないでください。
- 他の人に渡したり、他のインスタンスと使い回したりしないでください。インスタンスごとにアプリを作ります。
- **漏れた・漏れたかもしれない** と思ったら、すぐに「OAuth2」の画面で「**Reset Secret**」を押して作り直し、設定ファイルの `DISCORD_CLIENT_SECRET=` を新しい値に書き換えて反映します（`smash-hub restart`）。作り直すと古いシークレットは使えなくなります。その後の対応は [インシデント対応](../security/incident-response.md#22-種類別の対応) に従ってください。

## 7. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| ログインのボタンがない、または押しても何も起きない | 設定ファイルの `DISCORD_CLIENT_ID` と `DISCORD_CLIENT_SECRET` が空になっていないか。書き換えたあと `smash-hub restart` で反映したか |
| Discord の画面で「Invalid OAuth2 redirect_uri」等と表示される | 4. のリダイレクト URI が、インスタンスのドメインと1文字も違わずに登録・保存されているか |
| Discord で許可したあと、インスタンスに戻ってエラーになる | クライアントシークレットが正しいか（作り直した場合は新しい値に書き換えたか） |
