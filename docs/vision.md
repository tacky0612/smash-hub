# ビジョン

## ミッション

**スマブラを楽しむプレイヤーの対戦の場と記録を、特定の誰かに依存せずに守り続ける。そして、どのサイトで遊んでいても、ほかのサイトのプレイヤーとも対戦でき、同じレート（SmashHubレート）で強さを比べられるようにする。**

## 解決したい課題

対戦レーティングサイトは、プレイヤーにとって「対戦相手を見つける場」であると同時に「自分の歩みの記録」でもあります。しかし個人運営のサイトでは次の問題が避けられませんでした。

1. **単一障害点** — 運営者の事情（負担・費用・生活の変化）でサービスが終わる。
2. **記録の消失** — サービス終了と同時に、何年分もの対戦履歴やレートが消える。
3. **負担の集中** — サーバー費用、障害対応、不正対応、問い合わせ対応が1人に集まり、それ自体が閉鎖の原因になる。

さらに、1つの大きなサイトが閉鎖すると、プレイヤーは複数の代替サイトに分かれて移っていきます。サイトが乱立すると、次の問題が起きます。

4. **記録とレートの分断** — 対戦記録がサイトごとに閉じ、レートはそのサイトの中だけの値になる。同じレートでも、サイトによって強さの水準が違い（サイト間の強さの偏り）、プレイヤー同士で比べられない。
5. **過疎サイトのマッチング不成立** — 利用者の少ないサイトでは、対戦を募集しても相手が見つからない。プレイヤーは人の多いサイトに集まり、小さなサイトは続けられなくなる（結果として、また1つのサイトに依存する）。

## SmashHub の答え

| 課題 | アプローチ |
|---|---|
| 単一障害点 | 複数の独立した運営者がサーバーを立て、相互に連携する（連合） |
| 記録の消失 | 対戦記録を複数サーバーへ複製する。記録は署名付きなので、どこに置かれていても本物か検証できる |
| 負担の集中 | 1台あたりの規模を小さく保ち、運営者・開発者を OSS コミュニティで分担する |
| 記録とレートの分断 | すべてのインスタンスが同じ署名付きの対戦記録を共有し、同じ計算式でレートを計算する。レートは連合全体で1つ（**SmashHubレート**）で、どのインスタンスでも同じ値になる |
| 過疎サイトのマッチング不成立 | 対戦募集をインスタンス間で配り合い、**別のインスタンスの利用者ともマッチングする**。小さなインスタンスの利用者も、連合全体の利用者と対戦できる |

SmashHubプロトコルは、SmashHub のインスタンス同士だけでなく、プロトコルを実装した他の対戦サイトも参加できる「レーティングの共通基盤」です（→ [SmashHubプロトコル](architecture/federation.md)、[ADR 0011](adr/0011-federation-participation-conditions.md)）。サイトごとに画面や運営方針が違っても、記録・レート・対戦相手を共有できます。

## 設計原則

1. **記録が主、サーバーは従** — 対戦記録は特定のサーバーではなくコミュニティ全体の資産。サーバーは記録を保持・中継する器にすぎない。
2. **レートは1つ** — レートはサイトごとに別々に持たず、共有された記録から全員が同じ手順で計算する1つの値にする。
3. **誰でも検証できる** — 記録は両プレイヤーの署名付き。レートは記録から決定的に再計算できる。運営者を信頼しなくても正しさを確認できる。
4. **小さく運用できる** — 個人が安価な VPS 1台で運用できることを前提にする。重い依存やスケールアウト前提の構成を避ける。
5. **やめやすく、引き継ぎやすい** — 運営者がやめるときに、データと利用者を他のサーバーへ引き継げる手順をソフトウェアとして用意する。
6. **スモールスタート** — 最初から完全な分散システムを目指さない。単一サーバーで価値を出しつつ、データ設計だけは最初から分散前提にする（→ [ロードマップ](roadmap.md)）。

## やらないこと（Non-goals）

- **収益化** — プロジェクトとして収益を得ず、広告・有料機能・課金をソフトウェアに実装しない（→ [運営ポリシー](policy.md)）。連合には営利のサイトも参加できるが、その営利活動にプロジェクトは関与しない。
- **公式素材の利用** — 任天堂の利用許可が出ている素材以外は使わない。
- **ブロックチェーン / 暗号通貨** — 改ざん検知には電子署名とハッシュチェーンで十分であり、トークンや手数料の仕組みは持ち込まない。
- **大会運営プラットフォーム** — 当面は「野良対戦のマッチングとレーティング」に集中する。大会機能は将来の検討事項とする。
- **ゲームとの直接連携** — ゲーム本体やネットワークへの解析・改変・自動化は行わない。対戦はプレイヤーがゲーム内で行い、結果は人が報告する。

## 成功の定義

- 最初の運営者がいなくなっても、サービスと対戦履歴が継続している。
- 3つ以上の独立した運営者によるサーバーが連携して稼働している。
- どのインスタンスでも同じ戦績・同じレートが表示され、利用者の少ないインスタンスの利用者も待ち時間なく対戦相手が見つかる。
- 運営者が1人で抱える作業が「サーバーを動かし続けること」程度に収まっている。
