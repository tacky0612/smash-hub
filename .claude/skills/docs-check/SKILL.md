# docs-check

SmashHub のドキュメントを **機械的なチェック（スクリプト）** と **内容の整合性レビュー（判断を伴う確認）** の2段階で確認する。

## 手順

### 1. 機械的なチェック

リポジトリのルートで実行する。

```bash
python3 .claude/skills/docs-check/scripts/check_docs.py
```

スクリプトが検出するもの:

| 種別 | 内容 |
|---|---|
| リンク切れ | 相対リンク先のファイルがない / 見出しアンカーがない / リポジトリ外を指している |
| 目次漏れ | `docs/` 配下のドキュメントが [docs/README.md](../../../docs/README.md) からリンクされていない（ADR 個別ファイルは除く） |
| ADR | [docs/adr/README.md](../../../docs/adr/README.md) の一覧に載っていない / 番号の重複・欠番 / ステータス行がない・値が不正 / 一覧とステータスが食い違う |
| ステータス表記 | `docs/architecture`・`domain`・`security`・`operations` のドキュメント冒頭に `> ステータス:` がない（警告） |

外部リンク（`https://` 等）は確認しない。必要ならユーザーに確認してから WebFetch 等で確かめる。

### 2. 内容の整合性レビュー

スクリプトでは分からない食い違いを、変更されたファイルを中心に確認する。`git diff` / `git status` で変更範囲を把握し、変更内容に関係するドキュメントを読む。変更範囲が分からないときや、ユーザーが全体のチェックを求めたときは全ドキュメントを対象にする。

確認する観点:

1. **ポリシーの不変条件** — 次と矛盾する記述がないか。
   - 任天堂の利用許可が出ている素材以外を使わない（[docs/policy.md](../../../docs/policy.md)）
   - 収益化しない
   - 個人情報（メールアドレス・パスワード・外部アカウント名・トークン）を保持しない、パスワード認証をしない（[docs/security/data-protection.md](../../../docs/security/data-protection.md)）
   - 連合で共有するデータは追記のみ、レート計算は決定的
2. **同じ事実の重複箇所** — 次のように複数箇所に書かれている事実が揃っているか。
   - 個人情報・認証の方針: `README.md`・`docs/policy.md`・`docs/security/*`・`docs/operations/server-covenant.md`・`docs/architecture/overview.md`・`AGENTS.md`
   - バックエンドの構成: `docs/architecture/backend.md`・`backend/README.md`・`AGENTS.md`・実際の `backend/` のディレクトリ（`find backend -type d` で突き合わせる。現在は層までで、層の下は予定）
   - 認証プロバイダー: `docs/security/authentication.md`・`docs/adr/0002-*`・`docs/tech-selection.md`・`docs/roadmap.md`
   - リポジトリ構成: `README.md`・`AGENTS.md` の構成図と実際のファイル
   - 保持期間などの数値（アクセスログ 14日、対戦ルームのメッセージ 7日、閉鎖予告 7日 等）
   - 紹介サイト: `site/src/pages/*.tsx`・`site/src/components/diagrams/*.tsx` はドキュメント（SmashHubプロトコル・入門・運営ポリシー・約束事・データ保護）の要約。元のドキュメントの変更がサイトに反映されているか
3. **用語** — [ユビキタス言語](../../../docs/domain/README.md) と異なる用語・表記揺れがないか（例: 「サーバー」と「インスタンス」の混在は、運用者向けの平易な説明を除き「インスタンス」に揃える）。用語表にない新しい概念が出てきていないか。
4. **ADR との整合** — `Accepted` の ADR と矛盾する記述がないか。ADR が `Proposed` なのに本文で「決定済み」と書いていないか（逆も）。
5. **ロードマップとの整合** — 各ドキュメントで「Phase N で行う」と書かれた内容が [docs/roadmap.md](../../../docs/roadmap.md) のフェーズと一致しているか。
6. **未解決の論点** — 本文で決まったことが「未解決の論点」に残っていないか。

### 3. 報告

次の形式で報告する。問題がなければ「問題なし」と、実施したチェックの範囲を書く。

```
## docs-check 結果

### 機械的なチェック
エラー N 件 / 警告 N 件
- <ファイル:行>: <内容>

### 整合性レビュー（対象: <確認したファイルの範囲>）
- [要修正] <ファイル:行> — <食い違いの内容>（<食い違う相手のファイル:行>）
- [要確認] <ファイル:行> — <判断が必要な点>
```

### 4. 修正

- リンク切れ・目次漏れ・ADR 一覧の漏れなど **機械的に直せるもの** は、そのまま直してよい。直したら手順 1 を再実行してエラーが 0 件になったことを確認する。
- 内容の食い違いで **どちらが正しいか判断が必要なもの** は、勝手に直さずユーザーに確認する。
- `Accepted` の ADR は書き換えない（[docs/adr/README.md](../../../docs/adr/README.md) の手順に従う）。
